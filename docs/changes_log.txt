GIT COMMIT MESSAGES
================================================================

The following messages are ready to copy and paste into git commit
commands. They follow the Conventional Commits style used throughout
this project. Each message covers one logical feature or group of
related changes so the history stays readable.

────────────────────────────────────────────────────────────────
1. GUNICORN / PRODUCTION WSGI SERVER
────────────────────────────────────────────────────────────────

git commit -m "feat: switch from Django dev server to Gunicorn WSGI

Replace 'python manage.py runserver' with a two-step run command:
collectstatic followed by gunicorn plec_project.wsgi:application
bound to 0.0.0.0:5000. Matches the Procfile already used for
Heroku. Gunicorn handles concurrent requests correctly and is
appropriate for production use; the Django dev server is
single-threaded and explicitly not production-safe."

────────────────────────────────────────────────────────────────
2. SECURITY — HOST LOCKING & CSRF ORIGINS
────────────────────────────────────────────────────────────────

git commit -m "feat(security): lock ALLOWED_HOSTS and CSRF_TRUSTED_ORIGINS to exact domain at runtime

Read REPLIT_DOMAINS from the environment at startup and replace the
wildcard '*.replit.app' values with the exact host. Log a warning
if the env var is absent so the operator knows the wildcard fallback
is active. Add test_settings_host_lock.py to verify the locking
behaviour under both conditions."

────────────────────────────────────────────────────────────────
3. SECURITY — SECURITY.MD & .ENV.EXAMPLE
────────────────────────────────────────────────────────────────

git commit -m "docs(security): add SECURITY.md and .env.example

SECURITY.md covers: supported versions, responsible disclosure
contact (j.parman@dudleycol.ac.uk), out-of-scope items, and a
summary of the security measures built into the platform.
.env.example documents every required and optional environment
variable with inline comments and safe placeholder values. Safe
to commit — no real secrets included."

────────────────────────────────────────────────────────────────
4. PASSWORD RESET RATE LIMITING
────────────────────────────────────────────────────────────────

git commit -m "feat(auth): add email-keyed rate limiting to password-reset form

Throttle password-reset requests to 3 per hour per email address
using Django's cache framework (LocMemCache in dev, database cache
in production). Requests beyond the limit return HTTP 429 with a
styled password_reset_rate_limited.html page explaining the wait.
Prevents automated abuse of the reset endpoint without exposing
whether an email is registered."

────────────────────────────────────────────────────────────────
5. ADMIN AUDIT LOG
────────────────────────────────────────────────────────────────

git commit -m "feat(admin): log every admin password-change to the audit log

Write a Django LogEntry record whenever a staff member resets
a learner's password via the admin panel. Add a dedicated
AdminAuditLog proxy model and admin page showing actor, target
email, and timestamp. Add has_change_permission guard so staff
accounts cannot use the in-panel form to change superuser
passwords (privilege escalation prevention).

Tests added:
- Audit log entry created on password change
- Audit log lists entries from all admins, not just the current one
- has_change_permission blocks staff-on-superuser change
- AUTH_PASSWORD_VALIDATORS enforced on admin change form"

────────────────────────────────────────────────────────────────
6. BEST SCORES BY LEVEL
────────────────────────────────────────────────────────────────

git commit -m "feat(profile): add best-scores-by-level summary table to /profile/

Query AssessmentResult records for the signed-in user, group by
level_key, and annotate with the best (max) score and corresponding
grade. Display a sortable summary table above the full submission
list on /profile/: columns are Level, Best Grade (colour-coded
badge), Best Score (bar + number), and Attempts.

Tests added:
- TestBestScoreSummaryOnRetake: 10 tests verifying accuracy after
  multiple retakes per level
- TestBestScoresSummaryIsolation: user A's best scores are never
  visible on user B's profile"

────────────────────────────────────────────────────────────────
7. COURSE PROGRESS BAR (INTEL BAR)
────────────────────────────────────────────────────────────────

git commit -m "feat(home): add server-side course progress stat to home page

Pass levels_attempted (distinct level count from the signed-in
user's AssessmentResult records) through the template context and
render it as a fifth stat tile on the home page: 'YOUR PROGRESS
X / 6 LEVELS ATTEMPTED'. The value is calculated server-side on
every request so it cannot be spoofed via localStorage.
Unauthenticated visitors see the standard four tiles only.

Tests added (Jest + Django):
- updateProgressStat unit tests for bar-width accuracy (0–6)
- Per-user count isolation (user A count does not affect user B)
- Count decrements correctly after result deletion
- Bar width stays correct when total level count is exactly 6"

────────────────────────────────────────────────────────────────
8. PREREQUISITE NOTICES
────────────────────────────────────────────────────────────────

git commit -m "feat(challenge): add server-side prerequisite notices to levels 2–6

Serve a dismissible banner on levels 2–6 when the signed-in
learner has no saved result for the preceding level. Dismissal
state is persisted server-side (PrereqDismissal model) for
authenticated users so the notice stays hidden after login.
An un-dismiss DELETE endpoint is provided so the admin can reset
the state. Level 1 and all non-challenge pages are unaffected.

Tests added (Jest + Django):
- Notice shown when no prior result; hidden when result exists
- Level 1 never shows the notice
- Invalid PLC_LEVEL values do not trigger the notice
- Dismissal persists after the user logs out and back in
- Card dimming (applyProgressionState) DOM contract tests"

────────────────────────────────────────────────────────────────
9. REFLECTION LOG — FULL CRUD
────────────────────────────────────────────────────────────────

git commit -m "feat(reflect): add reflection log with full create / edit / delete

New routes and views:
  GET/POST  /reflect/              — create a reflection entry
  GET       /reflect/all/          — paginated list (10/page)
  GET/POST  /reflect/<pk>/edit/    — edit an existing entry
  GET/POST  /reflect/<pk>/delete/  — delete with confirmation

All views are LoginRequired. All object lookups use
get_object_or_404(Reflection, pk=pk, user=request.user) so one
user can never read, edit, or delete another user's entries.

ReflectionForm fields:
  - level: ChoiceField (6 challenges + 2 lessons)
  - skill_area: ChoiceField (7 areas)
  - notes: CharField, min 30 / max 1000 chars (custom validator)
  - confidence: ChoiceField 1–5 with plain-English labels

Templates:
  - reflect.html          create form + inline recent-entry count
  - reflect_list.html     paginated full list with edit/delete links
  - reflect_edit.html     pre-populated edit form + delete shortcut
  - reflect_delete.html   confirmation card with entry preview

Tests added:
  - Ownership isolation: cross-user 404 on edit and delete (10 tests)
  - Unauthenticated redirect on all three routes
  - POST ignores spoofed user field in request body
  - Reflection rows survive a password change"

HOW TO APPLY THESE COMMITS
================================================================

All changes listed above are already committed to the 'main' branch
in this workspace. The messages above are provided so they can be:

  a) Used verbatim when pushing to a public GitHub repository:
       git push origin main

  b) Used as reference when writing a project submission summary
     or portfolio entry explaining what was built and why.

  c) Copied into a CHANGELOG.txt update alongside version tags.

To push everything to GitHub in one go:
  git push origin main

To push to the separate Heroku git remote (for deployment):
  cd /path/to/heroku-repo
  # unzip the latest plec_project.zip
  git add -A
  git commit -m "Deploy: reflection log, best scores, progress bar, edit profile, admin audit log, rate-limited password reset, gunicorn"
  git push heroku main
